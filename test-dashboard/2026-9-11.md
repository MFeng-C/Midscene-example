# 2026-09-11 调度平台运行账号与缓存权限排查记录

## 一、问题背景

H5 双端业务测试返回 `step_failed`。初步怀疑调度服务账号跨用户访问以下 JDualAgent 缓存目录时缺少写入权限：

```text
C:\Users\xdd\AppData\Local\Juphoon\JDualStorage\JDualAgent\record
```

需要确认调度服务的实际 Windows 运行账号、目录 ACL，以及最新测试报告中的底层错误。为避免服务账号跨用户写入 `C:\Users\xdd`，最终要求调度平台使用 `xdd` 账号启动。

## 二、排查结果

### 2.1 原调度进程账号

原监听 `3001` 端口的进程信息如下：

```text
用户：HAPPY\CodexSandboxOffline
命令：node server/index.js
```

原服务并非由 `xdd` 账号运行。

可使用管理员 PowerShell 核实监听进程及账号：

```powershell
$conn = Get-NetTCPConnection -LocalPort 3001 -State Listen
$processId = $conn[0].OwningProcess
$process = Get-CimInstance Win32_Process -Filter "ProcessId=$processId"
$owner = Invoke-CimMethod -InputObject $process -MethodName GetOwner

[PSCustomObject]@{
  PID = $processId
  User = "$($owner.Domain)\$($owner.User)"
  CommandLine = $process.CommandLine
}
```

### 2.2 缓存目录权限

目录存在，所有者为 `HAPPY\xdd`，并且未关闭权限继承。检查到的主要 ACL 如下：

```text
HAPPY\xdd                         FullControl
NT AUTHORITY\Authenticated Users Modify
HAPPY\CodexSandboxUsers           ReadAndExecute（继承）
NT AUTHORITY\SYSTEM               FullControl（继承）
BUILTIN\Administrators            FullControl（继承）
```

其中 `Authenticated Users` 的 `Modify` 权限会继承到子目录和文件。从 ACL 本身看，原调度账号通常也应具备创建、修改和删除文件的权限，没有发现显式拒绝规则。

使用 `xdd` 账号在该目录创建并删除唯一命名的临时文件，两个操作均成功。因此已经确认 `xdd` 对缓存目录具有实际写入和删除权限。

检查命令：

```powershell
icacls "C:\Users\xdd\AppData\Local\Juphoon\JDualStorage\JDualAgent\record"
```

### 2.3 最新失败报告

本次检查的最新报告：

```text
D:\Projects\midscene-example\H5-e2e\.artifacts\dualrecord-e2e\dual\dual-business-flow\20260911-104134\mobile-browser\mobile-browser\h5-business-flow-dual-peer\20260911-104135\h5-business-flow-dual-peer.md
```

对应 JSON 中的最终错误为：

```text
status: step_failed
error: 业务流推进超时，当前没有找到可执行动作。
```

报告还记录了环境探测警告：

```text
SSL: CERTIFICATE_VERIFY_FAILED
certificate verify failed: EE certificate key too weak
```

浏览器随后仍然完成了业务房间连接、RTC 登录和入会。流程在“环境检测未通过，确认继续”之后没有找到下一步可执行动作并超时。报告中没有出现 `Access denied`、`EACCES`、`EPERM` 或缓存写入失败。

因此，现有证据不支持“缓存目录权限导致本次 `step_failed`”这一判断。当前应优先排查环境检测确认后的页面状态识别，以及 `run_business_flow` 的等待和超时逻辑。SSL 弱证书问题也应单独治理。

## 四、使用 xdd 账号启动调度平台

### 4.1 xdd 登录会话中前台启动

使用 `xdd` 登录 Windows，打开 PowerShell：

```powershell
cd D:\Projects\midscene-example\test-dashboard
npm start
```

这种方式适合调试。关闭终端或注销 `xdd` 后，服务会停止。

### 4.2 xdd 登录会话中后台启动

在 `xdd` 的 PowerShell 中执行：

```powershell
$workspace = 'D:\Projects\midscene-example\test-dashboard'

Start-Process `
  -FilePath 'D:\nodejs\npm.cmd' `
  -ArgumentList 'start' `
  -WorkingDirectory $workspace `
  -WindowStyle Hidden `
  -RedirectStandardOutput "$workspace\dashboard.stdout.log" `
  -RedirectStandardError "$workspace\dashboard.stderr.log"
```

本次实际采用的是该后台启动方式。它能确保当前进程使用 `xdd` 账号，但不提供开机自启或异常退出自动拉起。

### 4.3 长期运行建议

生产或长期使用时，建议通过 Windows 任务计划程序创建任务：

- 运行用户设置为 `HAPPY\xdd`。
- 操作设置为 `D:\nodejs\npm.cmd start`。
- 起始目录设置为 `D:\Projects\midscene-example\test-dashboard`。
- 根据实际需要选择“用户登录时”或“系统启动时”触发。
- 配置失败重试和运行日志。
- 创建后再次用本文 2.1 节命令确认 Node 子进程所有者确实为 `HAPPY\xdd`。

不建议仅给某个临时服务账号扩大 `C:\Users\xdd` 下的权限。更稳妥的方案是让调度服务始终以 `xdd` 运行，或者将 JDualAgent 缓存目录调整到固定服务账号自己的 `%LOCALAPPDATA%`。

## 五、验证清单

每次调整启动方式后执行以下检查：

1. `http://localhost:3001` 返回 HTTP 200。
2. 监听 `3001` 的 `node.exe` 所有者为 `HAPPY\xdd`。
3. `dashboard.stderr.log` 没有启动或权限错误。
4. 使用相同账号在 JDualAgent `record` 目录创建并删除临时文件成功。

6. 若仍出现“业务流推进超时”，转向排查环境检测确认后的页面状态和动作识别，不再优先归因于目录权限。

## 六、H5 双端循环调度支持

调度平台已接入 H5-e2e 的双端循环入口。页面提交的“循环次数”会作为 `--count` 参数传给：

```text
internal/dualrecord-e2e/scripts/run-loop-test.mjs
```

每轮执行顺序为：

```text
读取双端订单 ID
-> 将订单状态重置为 0 并校验
-> 执行 H5 + PC 双端测试
-> 等待 3 秒
-> 开始下一轮
```

具体行为：

- 订单 ID 明确从 `tests/dualrecord-e2e/dual-route-config.example.json` 的 `pc.orderId` 读取。
- 循环次数只允许 `1-100` 的整数，非法请求由 API 返回 HTTP 400。
- 每轮订单重置失败时立即停止，不再继续执行浏览器测试。
- 双端任务不再使用调度平台原有的任务级单次重置，避免与循环脚本重复重置。
- H5 和 PC 单端任务仍保留原有的任务执行前单次重置。

订单重置脚本必须通过环境变量获得数据库密码。启动调度平台前，在 `xdd` 账号的 PowerShell 中设置：

```powershell
$env:DUALRECORD_DB_PASSWORD = '<数据库密码>'
cd D:\Projects\midscene-example\test-dashboard
npm start
```

若使用任务计划程序，应在任务启动脚本或受控的系统环境中提供该变量。不要将数据库密码直接写入仓库、JSON 配置或本文档。现已为 `xdd` 配置用户级 `DUALRECORD_DB_PASSWORD`，并通过 `reset-order-state.js --dry-run` 完成数据库连接、订单查询验证；密码值未写入仓库或本文档。未配置该变量时，双端任务会在启动前明确失败并记录原因。
