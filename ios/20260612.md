# 一、客户纯录制业务流程

**测试脚本：** test_pure_recording_ios.py
**运行命令：** `python test_pure_recording_ios.py self`

## 测试流程概述

客户纯录制业务流程共覆盖 **15 个 Step**，完整流程如下：

```
客户登录 → 点击"纯录制"菜单 → 订单列表点击"录制" → 弹窗确认
→ 点击"同意并开始录制" → 点击"开始直播" → 3s倒计时后点击"同意检测"
→ 检测结果分支处理 → 录制流程(开始录制/结束录制/确认完成) → 文件上传
→ 点击"结束" → 点击"返回" → 进入"我的"退出登录 → 点击Home键
```

## 分支处理说明

### Step 8 检测结果分支

#### 分支1：检测未通过
```
检测未通过界面 → 点击"跳过" → 风险提示确认 → 等待播报节点 →
等待播报完成点击"下一步" → 等待朗读节点 → 业务办理完成界面
```

#### 分支2：检测通过
```
检测通过界面 → 等待播报节点 → 等待播报完成点击"下一步" →
等待朗读节点 → 业务办理完成界面
```

**注意：** 自助业务流程没有"完成录制"按钮，播报+朗读完成后自动跳转到业务办理完成界面。

## 测试流程概述


## 关键优化点

1. **WebView与原生混合操作** - iOS App多为H5页面，优先使用WebView点击，兜底使用原生Predicate
2. **多种按钮定位方式** - 支持xpath、accessibility id、predicate、class name等多种定位方式
3. **弹窗处理** - 支持WebView弹窗、Appium alert命令、原生Alert三种方式
4. **截图调试** - 每个Step后截图保存，便于问题诊断
5. **AI双录智能等待** - 问答节点需要等待AI播报完成后才能点击下一步，最长等待60秒
